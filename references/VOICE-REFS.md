# 声音样本：录制、保管与授权

**目录**：[一、录制要求](#一录制要求) · [二、指纹校验](#二指纹校验) · [三、保管与隐私](#三保管与隐私) · [四、授权](#四授权)

index-tts 把说话人的音色**和韵律**一起克隆，样本比参数更关键：同一位说话人换一段录音，克隆音的音高可差 12%–16%、语调起伏差 25%–40%。

## 一、录制要求

| 项 | 要求 | 原因 |
|---|---|---|
| 时长 | **10–14 秒**，硬上限 15 秒 | 上游只取前 15 秒，尾部静默丢弃且无日志；样本相似度在约 10 秒后饱和。样本在每句推理里作为 CFM 前缀参与扩散，缩短它会改变音色，别为提速去裁 |
| 内容 | 自然说话，语速语调贴近目标成片 | 音色与韵律风格都取自样本 |
| 环境 | 安静房间、单一麦克风距离、无背景音乐/混响/降噪痕迹 | 噪声会被一起克隆 |
| 说话人 | 仅一人 | 多人声会污染音色 |
| 格式 | WAV 16-bit；录 44.1/48 kHz 即可 | 上游无条件重采样到 22.05 kHz 单声道，录 96 kHz 无收益；削波是唯一真正伤相似度的电平问题 |

风格预设（story 等）是在作者本人的 `me-bright` 样本（12 秒，采样 32 kHz mono）上校准的。换样本要重新试听定档，别直接沿用预设数值。

## 二、指纹校验

用 `--expect-ref-sha1 <sha1 前 12 位>` 让 vibe-tts 在合成前核对样本，不符即拒绝。取指纹：

```bash
shasum <样本.wav> | cut -c1-12
```

为什么要校验：样本被悄悄换掉会让整批音频音色漂移，且缓存键里的 `ref_sha1` 会跟着变，旧缓存全部失效。

**永不原地覆盖样本**：服务端按路径缓存条件特征，覆盖同名文件后服务仍用旧特征；换样本就换文件名，并重启服务。

## 三、保管与隐私

声音是生物特征信息：

- 样本 wav **永不入库**：本仓 `.gitignore` 已忽略 `*.wav`、`*.mp3`；只保留指纹清单（若有）。
- 不贴进对话、不上传到任何第三方服务、不通过聊天工具传播。
- 服务 `ref_path` 是服务端本地绝对路径，服务只监听 127.0.0.1、无鉴权，别暴露到公网。
- 合成产物里含有克隆音色，分发前确认接收方与用途在授权范围内。

## 四、授权

- **本人声音**：由本人在对话里明确要求才使用 index-tts，并显式带 `--final-voice`（RSI-040）。Agent 不得自行提议、选用或替用户补加。
- **他人声音**：须取得本人**书面**同意，范围写明用途与分发渠道。
- 合成语音在目标平台发布时，按平台规则标注为 AI 合成。
- IndexTTS 采用 bilibili 模型许可证，商用需另行取得许可，见 [ENGINES](ENGINES.md)。
